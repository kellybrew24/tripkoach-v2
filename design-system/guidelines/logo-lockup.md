# Logo lockup — TripKoach

The TripKoach mark is a single **supplied badge**: a circular charcoal disc (`#303030`) with
gold star accents (`#D08028`). It is the only brand asset. It is **never redrawn, recoloured,
outlined, rotated, cropped, or reconstructed in code** — every appearance renders the same PNG.

This spec is the single source of truth for how the badge and wordmark are locked up, sized,
spaced, and labelled for assistive tech. It complements the visual card at
[`logo.card.html`](./logo.card.html) and the component at
[`../components/navigation/Logo.jsx`](../components/navigation/Logo.jsx).

## Lockups

Three approved lockups. Never invent others.

1. **Horizontal (default)** — badge + "TripKoach" wordmark on one baseline, gap `var(--space-2)`.
   Wordmark: `font-weight:800`, `letter-spacing:-0.03em`, colour `--text-strong` (ink) / `--n-0`
   (on dark). This is the header, footer, receipt and email lockup.
2. **Badge only** — the disc with no wordmark. Use in tight mobile headers, avatars/reply chips,
   favicons, and anywhere the word "TripKoach" already appears within the same block.
3. **Stacked** — badge centred above the wordmark. Reserved for splash / auth hero / share cards.
   Same clear space and colour rules as horizontal.

The `Logo` component covers lockups 1 and 2 via the `wordmark` prop.

## Clear space

Keep a margin equal to **25 % of the badge diameter** clear of other elements, text, or edges on all
four sides. At the 72 px reference that is 18 px; at the 36 px header size it is 9 px. Nothing —
including the wordmark of a *different* lockup — intrudes on this zone.

## Minimum sizes

| Context | Minimum badge height |
| --- | --- |
| Badge only | **28 px** (below this the star accents close up) |
| Horizontal lockup | badge **24 px** (wordmark stays legible at 18 px) |
| Favicon / touch icon | 16 px badge-only is acceptable *only* as a browser favicon |

## Tone & placement

- **On light** (`--n-0` / `--bg-page` / paper) — badge unchanged; wordmark `--text-strong`.
- **On ink** (`--n-800`/`--n-900`, hero overlays, footer) — badge unchanged (its charcoal disc reads
  on dark because of the gold accents); wordmark `--n-0`. Set the component `tone="inverse"`.
- Never place the badge on a busy photo without a scrim or a solid chip behind it.

## Misuse — never

Recolour · rotate · skew · crop · add shadows/glows/outlines · redraw or trace the star · stretch
(always lock aspect ratio via equal `width`/`height`) · place below the minimum size · box it in a
coloured tile that fights the disc · substitute a system emoji or icon font.

## Accessibility — alt text convention

The badge is imagery, not text, so its `alt` depends entirely on whether the word "TripKoach" is
already available to a screen reader in the same context:

- **Decorative → `alt=""`** when the badge sits next to the "TripKoach" wordmark or inside a control
  whose accessible name already says TripKoach (e.g. the header `Logo`, whose `<a>` carries
  `aria-label="TripKoach home"`; a reply chip labelled "Response from TripKoach"). A repeated alt
  would double-announce.
- **Informative → `alt="TripKoach"`** when the badge stands alone as the brand signal with **no**
  adjacent wordmark or naming text (auth-card logos, the receipt/email header badge, a bare footer
  mark). Screenshots in `screens-account.jsx` and the receipt header already follow this.

When the badge is a link on its own, prefer naming the **link** (`aria-label="TripKoach home"`) and
keeping the image `alt=""`, rather than putting the destination in the image alt.

Contrast: the badge is graphic, exempt from text-contrast rules; the wordmark inherits the measured
AA text tokens documented in [`accessibility.md`](./accessibility.md).
